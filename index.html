Data provenance. Every dot and every tile is read at runtime from assets/vectors.json, written by pipeline/build_vectors.py from nflverse player_stats: 10,700 player-seasons, 1999-2025, four positions, with each player's real name, team, games played and points per game. Coordinates are a PCA-3 of the 18-d per-game rate profile, z-scored within season across QB/RB/WR/TE. That claim is not taken on trust: scripts/build_gridiron_map.py recomputes the PCA and refuses to write anything unless it reproduces the shipped x, y and z, which it does at |r| = 1.0000 on all three axes. A view transform then rescales them into the canvas box and flips y so positive PC2 renders upward. No value on this page is generated, seeded, sampled or interpolated. What these coordinates are not. They are a projection of the feature profile, not of a learned embedding. The trained model's own output is a separate artifact, assets/embedding.json: MTNN v2 gated-fusion, 32-d, PCA-3, covering 503 players for the 2025 season only. Calling this an embedding map without that distinction would be an overclaim. How to read a cosine here. Unlike some sibling spaces, this one is not concentrated: two randomly chosen player-seasons sit at a median cosine near 0.00, so a tile's 0.99 is a genuinely close match rather than an artefact of the geometry. What was here before. This page drew 2,000 points from a linear congruential generator around five hardcoded centres, and the assets/vectors.json tracked on this branch held 1,000 rows named "player_0_16" through "player_999_x" with seasons numbered 0 to 5. The real export existed but had never been committed. It is committed here. Attribution: nflverse (nflverse.com) player_stats, free and permissive; built with numpy, no third-party data libraries.
